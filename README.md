# Лабораторно-практичне заняття №1: Програмні моделі систем координат

## 1. Короткий опис роботи

**Мета лабораторної роботи:** Спроектувати та реалізувати імутабельні програмні моделі для точок у 2D та 3D просторах, реалізувати перетворення між системами координат та порівняти продуктивність різних математичних підходів для обчислення відстаней.

**Реалізовані моделі (імутабельні структури `readonly struct` у C#):**

* `CartesianPoint2D`: Декартові координати на площині (x, y).

* `PolarPoint`: Полярні координати на площині (радіус, кут).

* `CartesianPoint3D`: Декартові координати у просторі (x, y, z).

* `SphericalPoint`: Сферичні координати у просторі (радіус-вектор, азимут, полярний кут).

Також реалізовані статичні фабричні методи для конвертації між цими системами та функції для обчислення відстаней (евклідова відстань, за теоремою косинусів, сферична хорда та дуга).

## 2. Інструкції для запуску проекту

Для запуску проекту необхідно мати встановлений **.NET SDK** (версії 6.0 або вище).

**Кроки для запуску:**

1. Відкрийте термінал (або командний рядок) у кореневій папці проекту (там, де знаходиться файл `.csproj`).

2. Виконайте команду компіляції та запуску:

   ```
   dotnet run
   
   ```

3. Програма автоматично виконає перевірку коректності перетворень та запустить бенчмарки для 100 000 пар точок (по 5 ітерацій для кожного підходу), після чого виведе медіанний час у консоль.

### Аналіз та висновки

* **Для 2D:** Декартова система координат демонструє значно вищу продуктивність. Це пов'язано з тим, що обчислення евклідової відстані базується на простих арифметичних операціях (додавання, віднімання, множення) та одному виклику кореня. Розрахунок у полярних координатах вимагає використання дорогої тригонометричної функції `Math.Cos()`, що суттєво уповільнює виконання циклу.

* **Для 3D:** Найшвидшим методом стабільно є розрахунок евклідової відстані у 3D Декартовій системі. Розрахунок хорди у сферичних координатах виявився значно повільнішим, оскільки вимагає багаторазових викликів `Math.Sin()` та `Math.Cos()` для кожної пари точок. Найповільнішим підходом є розрахунок сферичної дуги, адже окрім базової тригонометрії він додатково вимагає виклику оберненої функції `Math.Acos()` та перевірки на вихід за межі області визначення (`Math.Clamp()`).

## 5. Загальний висновок

Під час виконання роботи було закріплено навички проектування імутабельних структур даних (з використанням `readonly struct` у C#) та реалізації статичних фабричних методів. Найголовнішим інсайтом стало практичне підтвердження того, що складні математичні (особливо тригонометричні) функції мають значну обчислювальну вартість. З точки зору продуктивності, для масових ітеративних розрахунків вигідніше один раз сконвертувати дані у Декартову систему та використовувати просту арифметику, ніж виконувати розрахунки безпосередньо у полярних або сферичних просторах.
